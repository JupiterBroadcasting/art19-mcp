# Markers and Ads

ART19 supports two fundamentally different ad models. Each uses marker points, but the markers mean very different things.

## Two Models

### 1. Ad Insertion (SSAI) — `AdInsertionPoint`

Clean episode audio. Art19's server stitches ads in at playback time via server-side ad insertion.

```
Episode:  [clean audio here]
                  ↕ marker points + content rules
Playback: [PRE-roll ad] [clean] [MID-roll ad] [clean] [POST-roll ad]
```

**Workflow:**

1. Add `AdInsertionPoint` markers to tell Art19 *where* to insert ads
1. Add content rules to tell Art19 *what* to insert (campaign, live read, traditional spot)

Markers get auto-generated by Art19: pre-roll (position 0) and post-roll (end). Midrolls must be added manually.

**Key constraint:** Markers without content rules are dead ends — no ads serve.

**Content rule types:**

- `Campaign` — all ads from the AdExchange
- `LiveReadAd` — live-read ads (host-read sponsorships)
- `TraditionalAd` — ad spots with fixed creative

### 2. Embedded Ad Points — `EmbeddedAdPoint`

Ads are already baked into the audio file you upload. Markers serve as chapter markers only.

```
Episode (what you upload): [PRE-roll] [clean] [MID-roll] [clean] [POST-roll]
                         ↕ EmbeddedAdPoint markers tag each region
Playback: same as uploaded
```

**Workflow:**

1. Produce the final audio with ads already spliced in
1. Add `EmbeddedAdPoint` markers to tag where each ad region starts
1. No content rules needed

**Use case:** When you have one-off sponsorings that aren't sourced from the AdExchange, or you're working with fixed creative.

## Creating Markers via MCP

`create_marker_point`:

```clojure
{
  "episode_version_id": "abc-xyz-...",
  "position_type": 1,           ;; 0=pre, 1=mid, 2=post
  "type": "AdInsertionPoint",   ;; or "EmbeddedAdPoint"
  "start_position": 1200,       ;; seconds (omit for pre/post)
  "maximum_content_duration": 60,
  "maximum_content_count": 2
}
```

`create_marker_point_content_rule` (only for AdInsertionPoint):

```clojure
{
  "marker_point_id": "marker-uuid",
  "priority": 1,
  "content_type": "Campaign"   ;; or "LiveReadAd" or "TraditionalAd"
}
```

## One-Off Workflow with `prepare_episode_version`

For quick episode prep with markers baked in:

```clojure
prepare_episode_version(
  episode_id = "episode-uuid",
  markers = [
    {
      "start_position": 1200,     ;; 20 minutes in
      "position_type": 1,          ;; midroll
      "maximum_content_count": 2,
      "maximum_content_duration": 60,
      "type": "AdInsertionPoint",
      "content_type": "Campaign",
      "priority": 1
    }
  ]
)
```

Omit `markers` to copy from existing active version. Markers get a default content rule (Campaign, priority 1).

## Decision Tree

```
Do you have one audio file with ads already mixed in?
├── Yes → use EmbeddedAdPoint markers
└── No → use AdInsertionPoint with content rules
  
  Need dynamic/per-programmatic ad sourcing?
  └── Yes → AdInsertionPoint (requires content rules from AdExchange)

  Need fixed sponsor slots?
  └── Yes → use AdInsertionPoint + LiveReadAd content type
```

## Gotchas

- **EmbeddedAdPoint has no content rules** — no targeting, no server injection. The audio IS the final product.
- **AdInsertionPoint requires content rules** — a marker without a rule won't serve anything.
- **You can mix both** on the same version if needed (prerolls embedded, midrolls server-inserted, etc.)
- **prepare_episode_version with :type EmbeddedAdPoint** — you still need to supply the final mixed audio as `source_url`

### Marker Ordering Constraints

ART19 enforces incremental `position_type` ordering when creating markers on a version:

1. **Pre-roll (position_type=0) must be created first.** If created without `start_position`, the resulting `null` start blocks midroll creation. Fix: `update_marker_point(marker_point_id, start_position=0)` on the pre-roll, then create midroll.
1. **Midrolls (position_type=1) come second** — created after pre-roll with explicit `start_position` timestamps.
1. **Post-roll (position_type=2) can only be created after at least one midroll exists.** ART19 auto-assigns the post-roll position to end of audio — omit `start_position`.

**Why this matters:** If you create markers in the wrong order (e.g., midroll before pre-roll, or post-roll before midroll), ART19 returns a 422 error. The `prepare_episode_version` with `midrolls` param handles ordering correctly.

### Pre-roll start_position Gotcha

The pre-roll marker (position_type=0) works differently from midrolls:

- Pre-roll can be **created** without `start_position` (ART19 defaults to `null`)
- But a `null` start_position on pre-roll **blocks creation of subsequent midrolls**
- **Fix:** After creating pre-roll, explicitly set `start_position=0` via `update_marker_point`, then create midrolls
- This is only necessary when constructing markers manually — `prepare_episode_version` with `midrolls` auto-sets pre-roll `start_position: 0`

### Editing Markers on a Published (active) Episode

Once an episode version reaches `processing_status: "active"`, ART19 **locks its marker points** — any `create_marker_point` / `update_marker_point` / `delete_marker_point` call returns:

```
422 not_eligible_for_changes | Episode version cannot modify marker points when status is active
```

**Implications:**

- **Via MCP tools:** you cannot edit markers on a live episode. To change duration, add/remove a midroll, etc., you must create a **new version** (`copy_active_version: true` reuses the audio — no re-upload) on a draft, edit it, then submit + republish. This is the "backfill" flow.
- **Via the ART19 web UI:** you CAN edit markers on a live episode. Under the hood the UI performs a version copy + republish (the episode's `active_version_id` changes; a new `release_periods` entry appears). It just hides that from you.
- **Practical split:** use the UI for quick one-off tweaks on already-live episodes; use the new-version flow (see `docs/publishing-workflow.md`) for batch backfills where you're already swapping audio / adding midrolls.

**Ad slot duration defaults** (all tunable via `def ^:const` at the top of `art19_mcp.bb`):

- Pre-roll: **90s** (2 ads)
- Mid-roll: **single = 120s**, **2+ midrolls = 90s each** (3 ads)
- Post-roll: **180s** (2 ads)

These apply to new episodes and new-version backfills on the current server code. On a pre-deploy server pass them explicitly.
